# 军校系统 AI 助教改造方案（demo 期）

> 定位：在 l3-ai-assessment-demo 上搭建「AI 助教」产品形态，demo 期允许使用模拟数据，技术选型（登录、数据库）押后。

## 优化点总览

| # | 优化点 | 需求来源 |
|---|--------|----------|
| 1 | 每个人要有专属个人页和「最懂他」的助教 |
| 2 | 个人学习主页 | 进入系统不只有课程页，还要有个人页展示自己的助手 |
| 3 | 全站常驻桌宠助手 | 一进系统就有 AI 助手对话、提醒、引导 |
| 4 | 助教个性化定制 | 新人快速入门 / 老销售巩固，助教因人而异 |
| 5 | 短期记忆 + 长期记忆 | 课测信息喂给助教做短期记忆，课程总结沉淀为长期记忆 |
| 6 | 视频页陪伴助手 | 看视频时有 AI 在边上陪伴，可提问、按脚本回答 |
| 7 | 主动引导机制 | 每天打开系统，助教告诉你今天该看什么、复习什么 |

---

## 2. 个人学习主页

**需求来源**：产品期望「每个用户进入系统，不仅有课程页面，还有一个个人页面」，个人页展示自己的助手与学习状态。

**做法**：新增「个人主页」视图，与现有课程总览并列作为一级入口，包含六个模块：
1. 个人基础信息（注册三项 + 入职时间等模拟字段）
2. AI 助教对话区
3. 学习画像（能力雷达 / 薄弱点，数据来自现有评分系统）
4. 我的课程进度
5. 勋章墙（现有勋章数据）
6. 今日待办（助教生成的今日建议）

## 3. 全站常驻桌宠助手

**需求来源**：期望助教是半岛 IP 形象的桌宠，挂在网页上，用户打开网站就能看到它、跟它交互。

**做法**：全站右下角悬浮 IP 形象（立绘 + 呼吸动效）：
- 主动冒气泡说话（承载引导、提醒）
- 点击气泡展开为对话面板，可自由追问
- 所有视图（课程页、个人页、测验页）均可见

**待办**：需要拿到半岛 IP 图片文件放入 `public/`。

## 4. 助教个性化定制

**需求来源**：助教应「最懂他」，且同一助手既服务新人销售快速入门，也服务老销售巩固——即助教因人而异。

**做法**：注册信息（身份、主攻方向）注入助教的 system prompt：
- 新人：鼓励带教语气，按课程顺序推进
- 老销售：直接干货，按薄弱知识点跳着推
- 引导内容每次由 LLM 根据用户记忆现编（已拍板，接受其成本）

## 5. 短期记忆 + 长期记忆

**需求来源**：课前一测的信息实时喂给 AI 助手作为短期记忆，让它了解用户这门课学到什么；学完一门课，把总结信息沉淀到长期记忆，形成总体赋能。

**做法**：激活并修复现有 `lib/user-memory-system.ts`（现为半成品，接口断裂、仅存内存）：
- **短期记忆** = 当前课程的课前测结果 + 课后复测结果 + 本节学习行为（demo 期模拟数据也可），随对话上下文实时注入助教
- **长期记忆** = 每完成一门课，由 LLM 生成该用户的课程总结（掌握点 / 薄弱点 / 建议），写入用户档案，跨课程、跨会话生效

## 6. 视频页陪伴助手

**需求来源**：观看视频时边上有一个 AI 陪伴助手一起学习；AI 不主动提问（提问交给课后测试题库），但用户可随时提问。

**做法**：改造现有 `/api/course-chat`（已有雏形，目前仅挂在视频页答疑）：
- 答疑依据限定为本节课程脚本 / 知识点
- AI 不主动发起提问，仅在用户提问时回答
- 超纲问题温和收窄：「这个问题超出本节内容，建议先完成本节学习，稍后在测验中检验」，引导回学习主线

## 7. 主动引导机制

**需求来源**：「每天打开这个页面，可以跟我说今天可以看什么、上次遇到的问题该用哪门课解决、或该复习某个知识点」——通过随机引导帮用户发现自己的不足并导入对应课程。

**做法**：demo 期先做两个触发时机（同一机制，后续可扩展到测验后、看完视频、多天未回归等）：
1. **每天首次打开系统**：桌宠冒气泡 + 个人页待办，内容由 LLM 根据用户记忆现编（今日该学的课 / 该复习的知识点）
2. **点击桌宠时**：展开对话面板，助教基于记忆继续引导
